# CLAUDE.md

This file guides Claude (and other contributors) working in this repository.

## The project and its repositories

This is **Universal Music Player** (`SU2H1/Universal-Music-Player`), the music player that Real-Hi-Res became with version 2.0, together with the whole history of Real-Hi-Res. It is licensed under the GNU General Public License version 3 (`LICENSE`, `GPL-3.0-only` in `pyproject.toml` and `rust/Cargo.toml`). The old repository `SU2H1/Real-Hi-Res` stays at 1.12.1 and gets no further changes; everything from 2.0 on happens here. The product name is "Universal Music Player" (`realhires.APP_NAME`, `realhires::APP_NAME`, used for window titles, About, the LRCLIB User-Agent and the packages: `UniversalMusicPlayer-<version>-<platform>`, `UniversalMusicPlayer.exe`/`.app`, Rust `universal-music-player`); the quality checker keeps the name Real-Hi-Res, and so do the internals that users' files depend on: the Python package `realhires`, the command-line tools `realhires`/`realhires-cli`, the `REALHIRES_*` variables, the data and settings folders (`RealHiRes`, `realhires`), the "Real-Hi-Res backups" folder and the file formats. Releases need the repository secrets `VT_API_KEY` (required: the release waits for VirusTotal), `HYBRID_ANALYSIS_API_KEY` and `KASPERSKY_OPENTIP_API_KEY` in this repository too.

## Standing instruction: keep the docs current

Every change to behaviour, options, thresholds, verdicts, file layout, packaging or dependencies must update **both** `README.md` (the user-facing documentation) and this `CLAUDE.md` (the contributor/agent notes) in the same commit. If you add a CLI flag, document it in the README options table. If you change a detection threshold, update the "How detection works" section of the README and the tunables table below. If you change the GUI, check that the README "Desktop app" section and `docs/gui-screenshot.png` still match it. If you change packaging, update the README "Download" and "Building the packages" sections and `packaging/README-RELEASE.txt`. Add a line to the changelog at the bottom of this file for each notable change, and bump `__version__` in `realhires/__init__.py`, `version` in `pyproject.toml` and `[workspace.package] version` in `rust/Cargo.toml` together (`test_rust_port_has_the_same_version` checks the last one).

## Standing instruction: keep the Rust port equal to the Python version

`rust/` holds a Rust port of Real-Hi-Res (2026-11-24), released as a preview next to the Python packages since 1.12.0 (`UniversalMusicPlayer-Rust-<version>-<platform>`). It must judge every file exactly as the Python version does and shares its settings file and saved results. So every change to the detection rules or tunables, the reasons, summaries and notes, the flags, `FileResult` fields, the settings, the saved-results format (`store.py`, `DETECTOR_VERSION`, `SCHEMA_VERSION`), the CLI options or output, Fix, or the desktop app's behaviour must be made in `rust/crates/core` (and `rust/crates/cli` or `rust/crates/gui`) too, in the same commit. Build it with `cargo build --release` in `rust/`, run `cargo test` there (it includes a headless test of the whole desktop app) and run `python3 -m pytest -q`: `tests/test_rust_parity.py` compares the two versions on the synthetic library and fails on any difference in verdict, flag, reason or summary, or on a measurement that differs by more than rounding. It is skipped when the Rust CLI is not built, so build it before you claim the port is equal. `rust/README.md` describes its layout.

## Standing instruction: release first, then the antivirus scan

The user's rule since 2026-11-25 ("From now on release then av"): a release is published as soon as its packages are built, and its antivirus scan runs right after. `build.yml` does this: its `release` job needs only `prepare` and the ten package jobs and publishes with `packaging/RELEASE_NOTES.md` as the notes, and its `av-scan` job then calls `av-scan.yml` in refresh mode, which scans the published files with VirusTotal, Kaspersky and Hybrid Analysis and writes the "Antivirus scan results" section into the release notes. Keep that order. `.github/workflows/publish-run.yml` (Actions → "Publish a build now, scan after", input `run_id` of a `build.yml` run on main whose ten package jobs passed) does the same for an existing run (2.0.0 and 2.2.0 were published with it, before `build.yml` itself worked this way); cancel the source run first if it would publish too. If the scan job fails, find out why (the log shows each service's raw replies) and re-run it, or run `av-scan.yml` for the tag. After every release, check its "Antivirus scan results" section once the scan has finished, tell the user what it shows, and explain any detection. Check a detection by a major vendor yourself before calling it a false positive (for a flagged `.dmg`, unpack it with `7z` and compare every file's SHA-256 with the clean `.zip`, as was done for 1.10.0), then record the result in `packaging/av_reviews.json` and run `av-scan.yml` for that tag, so the release page shows the check instead of the warning. Only write down what was verified.

## What the project does

Since 2.0 the desktop app is a music player (Apple Music-like: a Library start page with fourteen entries, playlists, likes and dislikes, play history and "Your Stats", Now Playing with synced lyrics, Playback info, a graphic and parametric equalizer with named presets and Equalizer APO/AutoEQ import/export, gapless playback, themes with a theme editor, everything else in Settings), specified once for both versions in `docs/player-spec.md`; the 1.x app lives on as its Quality check page. `realhires` scans audio files or folders and classifies each file as FAKE LOSSLESS (a "fake FLAC": a lossless container with an MP3/AAC source, at any resolution), FAKE HI-RES (upsampled and/or bit-padded), SUSPICIOUS, REAL HI-RES, NOT HI-RES (genuine CD-quality lossless, labelled "CD quality" in the GUI), LOSSY FORMAT or ERROR. Every result also carries a one-line `summary` (the "Why" column) and machine-readable `flags`. It decodes the audio with FFmpeg and inspects the samples, so it never trusts tags or headers. Results are saved (`store.py`), so an unchanged file is never analysed twice, also across restarts and updates. Since 1.12.0 it also downloads synced lyrics from LRCLIB (lrclib.net) and saves them as `<name>.lrc` next to each song, following LRCGET's conventions (`lyrics.py`). There is a CLI (`realhires`) and a Tkinter desktop app (`realhires-gui`). Both are also shipped as self-contained PyInstaller packages, with FFmpeg bundled, for Windows x64, macOS arm64 (12+), macOS x86_64 (10.15+), Linux x64 and Linux arm64 (glibc 2.28+).

## Layout

| File | Role |
| --- | --- |
| `realhires/probe.py` | Contains `find_tool()`/`tool()` (FFmpeg lookup order: `$REALHIRES_FFMPEG_DIR`, then the PyInstaller bundle `_MEIPASS/ffmpeg`, then `ffmpeg/` next to the executable, then `PATH`), `probe()` (ffprobe to `AudioInfo`, including `tags` normalised by `normalize_tags()` across FLAC/ID3/MP4/APE/RIFF names), and `iter_pcm()`, which streams decoded audio as left-justified int32 `(frames, channels)` blocks. `LOSSY_CODECS` lives here. `_no_window()` suppresses console windows on Windows. |
| `realhires/analysis.py` | Contains `SpectrumAccumulator` (streaming Welch spectrum, Blackman-Harris window, about 6 Hz bins; with `spectrogram=True` it also keeps 256 linear bands × one row per 0.25 s, and `spectrogram_result()` returns it as zlib-compressed uint8 dB of at most 1200 columns), `BitDepthAccumulator` (lowest-set-bit histogram), `analyze_spectrum(..., cfg=)` (bandwidth, cliff test with the edge tie-break, lossy cliff scan), `compact_spectrum()` (a 900-point max-hold spectrum for the GUI), and `decode_spectrogram()`. Detection defaults are module constants. `detection_params(cfg)` maps a `Settings` object (or None, meaning the defaults) to the values actually used. Since 1.7.0 it also holds `GridAccumulator` with `_grid_step()` and the `Grid` result (a per-channel histogram of 24-bit values within ±65,536, whose DFT reveals the comb left by a scaled or dithered 16-bit master), the deep cliff and the −6 dB tie-break via `_midpoint_frequency()` inside `analyze_spectrum()`, the gap-limited bandwidth, the 26–40 kHz converter floor, and `converter_noise_floor(spec, cfg)`. |
| `realhires/settings.py` | The `Settings` dataclass, in which every field carries group, label, help, limits and kind metadata that the GUI uses to build its Settings window. It also provides `load()`/`save()` (JSON in the platform config dir or `$REALHIRES_SETTINGS`; invalid values fall back to defaults), `set_value()` for CLI `--set`, and `field_info()`. The group "Saved results" (1.9.0) holds `save_results`, `rescan_outdated` and `saved_graphs_mb`. `fix_after_scan` (Fixing, 1.10.0) is GUI-only; the CLI fixes only with `--fix`. The group "Lyrics" (1.12.0) holds `lyrics_existing` (choices = `lyrics.EXISTING_CHOICES`), `lyrics_plain`, `lyrics_instrumental`, `lyrics_search` and `lyrics_server`; none of them is a Detection setting, so they never change `settings_key()`. 2.1: `language` (Appearance, first; choices `i18n.LANGUAGES` = "English", "日本語") and `musicbrainz_auto` (off) and `musicbrainz_server` (Library). |
| `realhires/imaging.py` | NumPy-only colour maps (inferno/magma/viridis/gray), `spectrogram_rgb()`, `to_ppm()` (which the GUI shows through Tk's PhotoImage), `to_png()`, and `spectrogram_png()`, which draws the axis labels with a tiny bitmap font for CLI `--spectrogram`. |
| `realhires/verdict.py` | Contains `analyze_file(path, max_seconds, keep_spectrum, keep_plot, settings)` (the per-file pipeline, which never raises and turns failures into ERROR; `keep_spectrum` is for SVG, and `keep_plot` puts the compact spectrum plus spectrogram in `FileResult.plot`), `_judge()` (measurements to verdict, reasons, summary and flags; a lossy cut-off always wins and gives FAKE LOSSLESS), `FileResult` (`to_dict()` for JSON/CSV, `is_problem`), `verdict_breakdown()` (count and percentage per verdict, used by the CLI summary and the GUI pop-up), and `VERDICT_ORDER`/`PROBLEM_VERDICTS`. The grid test only runs for files that claim more than 16 bits or float, and `effective_bits` is the lower of the lowest-set-bit result and the grid's bit depth. Flags `value-grid` and `converter-floor` were added in 1.7.0. `DETECTOR_VERSION` (1.9.0: 1) is the version of the detection rules: bump it whenever a change can give a different verdict, flag, estimated resolution or measurement for the same file and settings, so saved results of older rules are marked outdated. `FileResult.saved` is set on results loaded from the store (`time`, `version`, `detector`, `outdated`, `graphs`, `moved_from`) and is left out of `to_dict()`; `saved_note()` turns it into the sentence the CLI (`-v`) and the GUI details show. A REAL file at 48 kHz or less gets `bit_depth_only_summary()` ("Genuine 24-bit at standard 44.1 kHz: hi-res by bit depth only") and `bit_depth_only_reason()` after `PASSED` (1.11.0). `update_wording(r)` brings the texts of results saved by older versions up to date when they are loaded (`store.result_from_json()` calls it); it is the way to change wording without a `DETECTOR_VERSION` bump, so extend it whenever a summary or reason text changes. |
| `realhires/store.py` | Saved results (1.9.0). `ResultStore` is one SQLite database (`results.sqlite` in `data_dir()`: `%LOCALAPPDATA%\RealHiRes`, `~/Library/Application Support/RealHiRes`, `$XDG_DATA_HOME/realhires`; `$REALHIRES_RESULTS` overrides it) with a `results` table keyed by `(path, skey)`. `skey` = `settings_key(cfg)`, a hash of the Detection settings only. `lookup(path, skey, wanted)` returns the result when size and `mtime_ns` match and `covers()` holds (a whole-file result answers any request, a partial one only requests for at most its `limit_s`); else it looks for a moved or renamed file with the same size and `mtime_ns` and the same `fingerprint()` (SHA-1 of the size and the first and last 64 KB), and copies that row to the new path. Results of an older `DETECTOR_VERSION` are returned with `saved["outdated"]`. `put(r, skey, wanted, plot)` never saves ERROR, deletes rows of the same path whose size or time differ, keeps graphs saved earlier for the same file when none are given, and every `_TRIM_EVERY` graph writes `trim_graphs()` drops the least recently viewed graphs (`used`, updated by `get_plot()`) above `saved_graphs_mb`. Results are JSON (`result_to_json()`, NaN/Infinity allowed, number-keyed dicts restored), graphs are zlib JSON plus the spectrogram bytes (`plot_to_blobs()`); nothing is pickled. A damaged file is renamed `.damaged-<time>` and a fresh one started; a newer schema (`SCHEMA_VERSION`) raises `StoreError`, and `open_store(cfg)` returns None then (or when `save_results` is off), so scanning works without the store. |
| `realhires/pool.py` | `MultiProcessPool` spreads workers over several `ProcessPoolExecutor`s, because Python on Windows caps one pool at 61 workers (the `WaitForMultipleObjects` limit). It also provides `split_workers()` and `effective_jobs()` (0 means one per CPU core, capped at 512). Both the CLI and the GUI use it. |
| `realhires/fix.py` | "Fix to real resolution". By default it fixes the file **in place** (same name, tags and cover art), so its properties show the real rate and bits, and the original is moved to `BACKUP_DIR_NAME` = "Real-Hi-Res backups" next to the file (`fix_backup`: folder, `.bak` or delete; `fix_backup_folder` for a custom folder). Copies are optional (`fix_output`). Rewriting the audio is required, because only editing the header values would change the playback speed. `target_resolution()` uses the source rate (`upsampled_from`, or the 44.1/48 family for lossy sources) and the real bits (16/24, optionally forced to 16 for CD-sourced files, per `fix_bits`). `plan_fix(result, cfg)` returns `(FixPlan, None)` or `(None, reason)`. `ffmpeg_command()` keeps tags (`-map_metadata 0`), copies cover art for FLAC/M4A, resamples with soxr, and adds triangular dither only for resample-to-16. `run_fix()` converts through `_convert()`, which tries, in order: `_exact_restore()` (for `FixPlan.exact_ratio` ≥ 2, a whole-number-ratio upsample to 16 bits: if exactly one sample phase holds only exact 16-bit values, as FFmpeg's default resampler leaves it, and the other phases do not, it keeps every Nth sample and verifies every kept sample while streaming, so the master comes back bit-exactly), `_resample_with_context()` (gapless joins, below), and the plain `ffmpeg_command()`. Both special paths feed raw PCM through `_Encoder`/`_pipe_command()`, which take tags and cover art from the original as input 1, and any failure falls back to the next path. `safe_source_rate()` is used by `target_resolution()`: a rate is only cut to when its own narrow or deep cliff passes and the −6 dB point (`upsample_mid_hz`) is not above 1.02 × its Nyquist; otherwise the next higher safe candidate, or the file's own rate, is kept. `prepare_gapless(plans, results, progress)` must run before any fix (the CLI and `FixDialog` call it): it orders each folder by disc, track and name, reads `CONTEXT_FRAMES` (8,192) frames at every join with a file that will be resampled, skips joins quieter than −70 dBFS on both sides, and for runs of consecutive gapless joins stores `context_before`/`context_after`, the exact `frames` (ffprobe `duration_ts`) and the `offset` on the run, so that `_resample_with_context()` can align the resampler input to the run's output grid and `atrim` exactly this track's samples. `run_fix()` writes to a temp file (`.realhires-*`), moves the original to its backup (restoring it if the final rename fails), renames the temp file, and re-analyses the result. `cli.iter_audio_files()` skips the backup folder and the temp files, so fixed originals are never rescanned. `Settings.from_dict()` migrates the 1.4.0 `fix_output` values. A 24→16 conversion without resampling goes through `aformat=sample_fmts=flt`, because FFmpeg's s32→s16 conversion truncates while flt→s16 rounds, so padded and only-dithered files come back bit-exactly. `FixPlan.dither` adds triangular dither for a value-grid file whose master was given a gain change. Since 1.10.0 `plan_fix()` explains skips: a fake lossless file already at its real rate and bits gets "Already 16/44.1, the resolution it really has: there is nothing to convert...", and a fake hi-res file whose cut was not safe gets the "Kept ... kHz" note. `skip_group()` maps a skip to a `SKIP_GROUPS` key (`lossy`, `uncertain`, `already`, `unknown`, `not-fake`), `skip_summary()` makes the counted sentence the Fix window and CLI `--fix` print, and `plan_fixes(results, cfg)` returns `(plans, [(result, reason)])` for the fake files among `results`. Since 1.12.0 `FixOutcome.how` records `"exact"`, `"gapless"` or `""`, `_prospect(r, cfg)` makes `plan_fix()`'s decision without touching the disk (no output path), for `fix_outlook(r, cfg)`, the few words of the GUI's "After fix" column and fact ("Fixable to 16/44.1", "16/44.1, stays fake: MP3/AAC source", "Stays fake: MP3/AAC source", "Stays fake: rate kept", "" for files that are not fake), and for `fix_advice(r, cfg)` (with `_keeps()`), the sentence the GUI details and CLI `-v` add to every fake file: what Fix does with it (via `plan_fix()`/`target_resolution()`) and whether it stays marked fake afterwards (lossy-sourced files always, files whose rate was kept by `safe_source_rate()`), so a file that is still fake after fixing and re-scanning says why; and `done_summary(outcomes, skipped, label)` returns the headline and sentences of the GUI's pop-up after fixing (fixed/failed counts with the first failure, the size before and after via `fmt_bytes()`, exact and gapless counts, where the originals went (one backup folder by its full path), the re-check verdicts named by `label`, with why fake lossless and kept-rate files stay fake, and the files left alone on purpose). |
| `realhires/eta.py` | Time left for a scan (1.11.0). `file_sizes(paths)` (unreadable = 1 byte) and `ScanEta(sizes, clock)`: `add(path)` per analysed file (repeats and unknown paths ignored), `seconds_left()` = bytes left × elapsed / bytes done, None until `MIN_FILES` (3) files and `MIN_SECONDS` (3 s), and `text()` via `fmt_left()` ("estimating the time left", "less than a minute left", "about N min left", "about H h M min left"), which appends " left" to `fmt_about()` (1.12.0, also used for the lyrics window's estimate). Bytes rather than files, because analysis time follows the amount of audio; reused saved results are never added, and parallel workers are covered because the throughput is measured for all of them together. |
| `realhires/lyrics.py` | Synced lyrics from LRCLIB (1.12.0), as LRCGET (the official LRCLIB client) does it; stdlib only. `LrclibClient(server, stop=, transport=, min_interval=, clock=, sleep=, rng=)` sends GET requests one at a time: `_throttle()` keeps request starts `min_interval` apart (`MIN_INTERVAL_S` 0.7 s, about 85/min, below LRCLIB's ~90/min for an identified client) and waits `MIN_GAP_S` (0.25 s) after each answer, 429/503 honour `Retry-After` plus up to 30 % jitter (`_not_before` also holds for the next song after a give-up), 5xx and network errors back off 1-2-4 s, `MAX_ATTEMPTS` 4, 404 = None, other 4xx raise `LyricsError` at once, an unverifiable certificate raises `LyricsError` "Could not connect … securely", and a set `stop` event raises `LyricsStopped` from any wait. `user_agent()` is "Real-Hi-Res v<version> (https://github.com/SU2H1/Universal-Music-Player)"; LRCGET's registered `Lrclib-App-Id` must never be sent (it identifies LRCGET). `default_interval(server)` reads `$REALHIRES_LYRICS_INTERVAL` (tests only) but never goes below `MIN_INTERVAL_S` for lrclib.net (`is_official()`). `ssl_context()` loads the first existing system CA bundle (`_CA_FILES`) when the default context has no CA certificates, because a frozen OpenSSL looks in the build machine's paths. `Track` (path, title, artist, album, duration; `params()` joins FFmpeg's ';'-separated artists with ', ' and sends `duration` rounded only within 1..3600; `primary_artist` for the search), `track_from_tags()`, `read_track(path, result)` (a scan result's tags and duration, else `probe()`; unreadable files raise `LyricsError`). `parse_record()` prefers synced > plain > instrumental and derives plain lyrics from synced ones (`strip_timestamps()`); `find_lyrics(client, track, search)` asks `/api/get` and, unless it gave synced or instrumental lyrics, `/api/search` (track_name + primary artist), where `best_match()` requires the same `normalize_name()` title (NFKC, casefold, bracketed parts, " - … Remaster" and "feat." removed, punctuation ignored, every script kept), the same artist (or one containing the other as words), and a length within `DURATION_TOLERANCE_S` (2 s; without a known length only the same album), ranking synced, then length difference, then album. Files: `sidecar(path, ext)`, `existing_lyrics()`, `skip_reason(path, cfg)` (an .lrc skips unless "Download again and replace them"; a .txt skips only with "Skip songs that have any lyrics"), `save_lyrics()` (synced → .lrc, plain → .txt when `lyrics_plain`, instrumental → .lrc holding `INSTRUMENTAL_LRC` "[au: instrumental]" when `lyrics_instrumental`; an existing .txt is kept unless replacing; `dry_run` says "Would save"), `write_text()` (UTF-8, '\n', through a `.realhires-lyrics-*.tmp` file and `os.replace`), and `read_lyrics_file()` for the GUI tab. `fetch_for_file()` never raises except `LyricsStopped` and returns a `LyricsOutcome` (status `SYNCED`/`PLAIN`/`INSTRUMENTAL`/`PLAIN_ONLY`/`NOT_FOUND`/`SKIPPED`/`NO_TAGS`/`FAILED`, full-sentence `message`, `track`, `written`, `how` "exact"/"search"); `short_status()`/`short_skip()` give the GUI's table cells, `STATUS_LABEL` the CLI's, `run_lyrics()` iterates paths with one client, `lyrics_summary()` counts outcomes, and `check_server()` makes one test lookup (CLI `--check-lyrics-server`). ## Detection tunables (`realhires/analysis.py` defaults, user-adjustable in `realhires/settings.py`)

Users change these in the GUI Settings window or with CLI `--set` (the settings name is given in brackets). The module constants are the defaults and must stay equal to the `Settings` defaults, which `test_settings_defaults_match_detection_constants` enforces. If you add a tunable, add it in both places and to `detection_params()`.

| Constant | Value | Meaning |
| --- | --- | --- |
| `CLIFF_DB` / `CLIFF_STRONG_DB` (`cliff_db` / `cliff_strong_db`) | 25 / 40 dB | The level drop from 88–96 % to 102–112 % of a candidate source Nyquist that means "upsampled", at medium and high confidence. |
| `DEEP_CLIFF_DB` / `DEEP_CLIFF_STRONG_DB` (`deep_cliff_db` / `deep_cliff_strong_db`) | 45 / 60 dB | The deep cliff: the drop from 88–96 % to the 25th percentile of 104–130 % of that Nyquist, which catches soft resamplers (FFmpeg's default swr) that are still falling inside the narrow window. Natural roll-offs of up to 72 dB/octave stay below 35 dB. Each test must pass its own base threshold; its strong level only raises the confidence. |
| `MID_RATIO` (`mid_ratio`) | 0.975 | When several candidates pass (and a neighbour within ±10 % reaches half a threshold), pick the one whose Nyquist best matches the −6 dB point (soxr about 0.955, swr 1.0). Replaced `EDGE_RATIO`/`edge_ratio` (−20 dB point) in 1.7.0; an old `edge_ratio` in a settings file is ignored. |
| `MAX_TREND_DB_PER_OCT` | 45 dB/oct | The steepest music slope that `_midpoint_frequency()` extrapolates. Its trend line is fitted over 68–80 % of the lowest candidate Nyquist and anchored at the top of that band. |
| `STEEP_DROP_DB` (`steep_drop_db`) | 20 dB | The drop across the bandwidth edge that counts as a brick wall, used by the fallback upsample rule. |
| `LOSSY_CLIFF_DB`, `LOSSY_MIN_HZ`, `LOSSY_MAX_HZ` (`lossy_cliff_db`, `lossy_min_khz`, `lossy_max_khz`) | 25 dB, 11 kHz, 20.3 kHz | The lossy-encoder low-pass search, which gives FAKE LOSSLESS. |
| `CONTENT_MARGIN_DB` (`content_margin_db`) | 10 dB | How far content must sit above the floor reference. |
| `RELEVANT_RANGE_DB` (`relevant_range_db`) | 110 dB | Content further below the spectral peak than this is ignored, which drops resampler images. |
| `BANDWIDTH_GAP_HZ` | 3 kHz | Content above an empty stretch wider than this does not extend the bandwidth (it drops swr images and spurs). For an upsampled file the bandwidth is also capped at the source Nyquist. |
| `ULTRASONIC_HZ` (`ultrasonic_khz`) | 24.5 kHz | A high-rate file with bandwidth below this and no cliff is SUSPICIOUS, unless `converter_noise_floor()` holds. |
| `SMEAR_HZ` | 4.3 kHz | A bandwidth up to this far above `ultrasonic_khz` (28.8 kHz by default), with only rounding noise in 26–40 kHz, is also SUSPICIOUS, because a soft resampler smears the 24 kHz edge this far. |
| `ANALOG_FLOOR_DB` (`analog_floor_db`), `FLOOR_TILT_DB` | 15 dB, 6 dB | `converter_noise_floor()`: the 26–40 kHz median must be this far above the rounding noise (TPDF dither adds only about 5 dB, real converters 25–40 dB), and its two halves must agree within 6 dB. |
| `FLOOR_STEP_DB`, `FLOOR_DEEP_STEP_DB` | 8 dB, 15 dB | ... and the narrow and deep cliffs at 22.05 and 24 kHz must stay below these (a re-recorded CD shows its own 16-bit floor stepping down). |
| `GRID_STRENGTH` (`grid_strength`), `GRID_FULL` | 0.35, 0.8 | The normalised comb strength that proves a value grid (real 24-bit audio stays below 0.05, a scaled 16-bit master reaches 0.85–1.0), and the strength above which the reason says that every sample is on it (below it, it describes the partial grid a 2× upsample leaves). |
| `GRID_WINDOW`, `GRID_MIN_SAMPLES`, `GRID_MIN_STEP`, `GRID_MAX_STEP` | ±65,536, 5,000, 6, 2,048 | The value range (24-bit scale) of the grid histogram, the samples per channel needed to decide, and the grid steps searched for (a 16-bit master at −32 to +18 dB). |
| `BIT_THRESHOLD` (`bit_threshold_pct`) | 0.5 % | The share of samples needed for a bit position to count as used. |

Candidate source rates are limited to `rate * 1.5 <= file_rate`, so a 96 kHz file is never accused of being upsampled from 88.2 kHz. The grid's bit depth is `16` when `log2(2 * peak / step)` is at most 16.1, and the next whole number above it otherwise; grids of 23 bits or more are ignored.

## Conventions and gotchas

- ffmpeg output is always `-f s32le -acodec pcm_s32le`. The bit-depth test relies on ffmpeg left-justifying integer samples, and on float-to-s32 conversion being undithered, which is the swresample default. The value-grid test relies on the same left-justification and shifts samples right by 8, so it always works on the 24-bit scale.
- Always call FFmpeg through `probe.tool("ffmpeg")` / `tool("ffprobe")` with `**_no_window()`, never through a bare `"ffmpeg"` string, or the packaged builds break.
- Spectrum levels are per bin and normalised so that a full-scale sine reads 0 dB. They are therefore much lower (about -60 dB for music, about -180 dB for a 24-bit floor at a 16k FFT) than the levels shown by spectrum viewers with small FFTs. `quantization_floor_db()` gives the theoretical floor.
- `analyze_file()` must never raise. Any exception becomes `verdict=ERROR` with the message in `reasons`.
- Saved results (`store.py`): bump `verdict.DETECTOR_VERSION` whenever a change can alter any verdict, flag, estimated resolution or measurement for the same file and settings (not for wording only), and note the new value in its comment. A wording-only change of a summary or reason goes into `verdict.update_wording()` instead, so saved results show the new text without a re-scan. Users then keep seeing their results, marked as made by older rules, and choose when to re-scan, which is what the user asked for: never force a re-scan on update. A new Detection setting changes `settings_key()` and so re-analyses everything once; that is intended. A SQLite connection belongs to its thread, so every thread opens its own `ResultStore` (`open_store()`). Never pickle into the store. Anything new that `FileResult` carries is saved automatically by `result_to_json()`; a dict keyed by numbers must be added to `_INT_KEYS`. Changing the table layout needs a `SCHEMA_VERSION` bump and a migration in `_connect()`.
- `analyze_spectrum()` receives the lower of the lowest-set-bit depth and the grid depth, so a file found to be a scaled 16-bit master gets a 16-bit quantisation floor for its bandwidth and converter-floor measurements.
- When you tune the spectral thresholds, test against both genuine spectra (steep natural roll-offs, with and without a converter noise floor) and fakes made with soxr and with FFmpeg's default swr at several filter sizes. Synthetic music without any noise floor is unrealistic; real converters always add one.
- `FileResult.spectrum` holds large arrays. It is only kept for `--plot` and is cleared after plotting. `FileResult.plot` is the small GUI version. Anything that the estimated-resolution logic needs must be copied onto `FileResult` fields, never read from `spectrum`.
- GUI worker processes use the **spawn** context, so any script that starts the GUI must guard its code with `if __name__ == "__main__":`. Otherwise every worker re-runs the script and opens another window. Frozen entry points must call `multiprocessing.freeze_support()` first.
- Every external program must be started with `probe.external_env()` (it is included in `_no_window()`). A frozen Linux build sets `LD_LIBRARY_PATH` to its bundled libraries, and a system ffmpeg or `xdg-open` that inherits it loads the bundle's old `libstdc++`/`libX11` and crashes.
- Linux packages must stay buildable on glibc 2.28, because CI enforces it. Do not add `MAX_GLIBC` exceptions. Instead, find out why a library needs a newer glibc. The spec deliberately leaves out `libfontconfig`/`libfreetype` so that the desktop's own copies are used, because an old bundled fontconfig cannot parse newer configs. Frozen Tk also needs the system `libxcb`, which every X11/XWayland desktop has.
- macOS minimums are declared through `REALHIRES_MACOS_MIN` (into `LSMinimumSystemVersion`) and verified by `check_compat.py`. If a dependency raises its minimum, CI fails, and you must then either raise the documented minimum (README, RELEASE_NOTES, README-RELEASE, the workflow) or pin the dependency.
- Do not edit `Info.plist` or any file inside the built `.app` after PyInstaller has signed it, because that breaks the ad-hoc signature and Apple Silicon then reports the app as "damaged".
- Never create a `ProcessPoolExecutor` directly. Use `pool.MultiProcessPool(effective_jobs(...))`, otherwise Windows users with more than 61 jobs get a `ValueError`. Settings `jobs` is 0..512, where 0 means automatic.
- Gapless joins only work when every track of a run is read before any of them is replaced, which is why `prepare_gapless()` keeps the neighbours' edges in memory (only for joins that are not silent). The resampler input must start on a multiple of the rate ratio's denominator relative to the run's first track, or the tracks land on shifted output grids (a fraction of a sample, which is audible at high frequencies). `test_fix_keeps_gapless_joins` compares the joined tracks with the album converted in one piece and fails at about −26 dB without the context.
- `fix.run_fix` must never lose user files unless the user chose "Delete it (no backup)", which the GUI confirms. It uses unique backup and copy names, writes to a temp file before moving the original, and puts the original back if the final rename fails. Keep the tests for tags, replace mode and the backup folder passing.
- Antivirus false positives on Windows (1.8.1): keep the Windows build free of the traits PyInstaller programs get flagged for. The `windows` CI job installs PyInstaller with `--no-binary pyinstaller` and `PYINSTALLER_COMPILE_BOOTLOADER=1`, so the launcher is compiled on the runner instead of the prebuilt one shared with malware. The spec sets `append_pkg=False` on Windows (the archive becomes `<name>.pkg` beside a ~100 KB launcher; `REALHIRES_APPEND_PKG=0/1` overrides it for testing), adds a `VSVersionInfo` to both executables, and builds `build/realhires.ico` with uncompressed BMP images. UPX stays off. Do not switch to one-file mode, which unpacks to a temp folder at every start and is flagged far more often. `check_windows.py` guards the first three in CI.
- Executable names must not differ only by case (`UniversalMusicPlayer` vs `realhires`), because Windows and macOS file systems are case-insensitive. That is why the CLI in packages is `realhires-cli`.
- On Linux the GUI uses the `clam` ttk theme, whose progress bar is invisible by default, so `main()` sets an explicit bar colour.
- You can test the GUI headlessly with `xvfb-run` and take screenshots with ImageMagick `import -window root out.png`. Without a display, `gui.main()` prints a clear message and returns 1.
- Local Linux package builds: inside the cloud dev container, dockerd can be started and `almalinux:8` run with `--network host`, with the proxy CA mounted and the repo `baseurl` used instead of `mirrorlist`.
- The tests must stay self-contained. Generate audio in fixtures instead of committing audio files. They must pass with both the distro FFmpeg and the bundled BtbN/Riedl builds used in CI.
- Always use full, specific sentences in user-facing reasons, because they are printed verbatim in the CLI and the GUI. Keep each `summary` to one short line (under about 70 characters), because it fills the "Why" column.
- New verdict strings must be added to `VERDICT_ORDER`, `settings.ALL_VERDICTS`, `gui.VERDICT_STYLE`, `report._COLORS` and the README verdict table.
- Settings files carry `_version` (`settings.SETTINGS_VERSION`). When an old saved value must change meaning, bump it and migrate in `Settings.from_dict()`, as was done for `fix_output` in 1.6.0.
- Settings are passed to worker processes by pickling, so `Settings` must stay a plain dataclass. Changing a field name breaks users' saved files only softly (the value falls back to its default), but document the change in the changelog.
- CLI output must survive legacy consoles. A Windows cp1252 console cannot encode `→`, `█` or Japanese file names, and CI caught a crash from exactly that. `report.setup_console()` (called first in `cli.main`) replaces unencodable characters and writes UTF-8 when output is redirected, and `report.arrow()`/`bar_char()` fall back to ASCII. Any new non-ASCII output must go through the same path. `test_cli_survives_legacy_console_encoding` and the smoke test's Japanese file name guard this.
- LRCLIB (`lyrics.py`) is a free service with published rules for programs, and the user's IP can be banned if they are broken: send its requests one at a time (one `LrclibClient` per run, one `LyricsDialog` at a time, never a thread pool), keep `MIN_INTERVAL_S` and `MIN_GAP_S`, always honour `Retry-After`, and name the program in the User-Agent. Never send LRCGET's `Lrclib-App-Id`; Real-Hi-Res could register its own. Send only the tags and length of a song, never its path or file name.
- The lyrics feature must never change audio files or delete lyrics files; it only writes `<name>.lrc`/`<name>.txt` through a temp file. Keep LRCGET's conventions (`.lrc` for synced lyrics, `.txt` for plain ones, `[au: instrumental]`) so files are shared with LRCGET.
- Tests must never contact lrclib.net: use `FakeLrclib` (and the `lrclib` fixture). Only the release smoke test asks lrclib.net once, and only certificate failures may fail it.

- CI lessons of 2.3 (each failed a test on a runner once): the Windows and macOS runners have 1024 x 768 screens, so pages are narrow there (about 800 px beside the sidebar): never assume a wide window in a test, check the layout the real width gives (`xvfb-run -s "-screen 0 1024x768x24"` reproduces it), and never let a row of buttons hide its last ones (`FlowRow`, `horizontal_wrapped`); on macOS Ctrl-click is a right-click, so multi-select is Cmd-click (Tk's Mod1, event state 0x8) and hints name Cmd; key events go to the widget with the keyboard focus, which the clicked widget may not get on the macOS runner (the window is not the active one), so handle keys such as Esc for the whole window; on Windows Button-4/5 are the mouse's side buttons, while X11 reports a sideways scroll as Shift-Button-4/5 (send Shift-MouseWheel elsewhere); a Tk Canvas's `lift()` raises its items, not the widget (use Tk's `raise`); never name a Tk method `_configure` (Tk's own).
- Do not use emoji in Tk widget text. Several Linux fonts cannot render them (the folder glyph showed as a box).
- 2.2: the apps have no menu bar; anything a menu held must also be a button, a menu on the page (the Quality Check page's More) or a key binding of its own.
- Mouse side buttons: Tk 8.6 rejects `<Button-6>`..`<Button-9>`, so they come through a plain `<ButtonPress>` (`nav_button()`): X11 8/9, Windows and macOS 4/5. Bind the wheel's buttons 4/5 only on X11 (`bind_wheel()`), or a side button scrolls on Windows/macOS. egui: `PointerButton::Extra1`/`Extra2`.
- egui tests: a pointer press needs its release in a later frame (else `pointer.any_down()` stays true and Settings never apply); modifiers come from `Event::ModifiersChanged`; a wheel scroll shows a frame later. Never sort or group per frame in egui (`cached_list()`).
- Tk `show_page()`'s first parameter is `name`, so pages take `kind=`/`group=`, never `name=`.
- Tk tests wait through `root.mainloop()` with `after()` checks that call `root.quit()`, as the app runs, not through `root.update()` in a loop: on the Apple Silicon runners one such `update()` call never returned (`tests/test_covers.py` scroll script, 2.2.0 release entry).
- Bit-perfect: the Python app on Windows can open WASAPI exclusive mode only in the device's Default Format (miniaudio 0.11's limit); 32-bit integer songs go through float and keep 24 bits. The exclusive, `hw:` and CoreAudio paths are only compiled and reviewed here (no sound hardware); test changes there on CI and ask the user to try them.
- Covers: pictures of type 3 and type 0 are both covers (iTunes and FFmpeg write type 0). FFmpeg's own decode of M4A/AIFF prints harmless warnings, so only native formats are checked for a clean decode.

- 1.8.0 (2026-11-21): Fix became safer and more faithful. It never lowers the sample rate below a frequency where the spectrum has clearly collapsed and the music has already dropped 6 dB (`safe_source_rate()`), so a doubtful source-rate estimate errs upwards instead of cutting content. Whole-number-ratio upsamples of 16-bit masters made with FFmpeg's default resampler (48 → 96/192 kHz, 44.1 → 88.2/176.4 kHz) are restored bit-exactly by keeping every Nth sample, after checking each of them. Gapless albums stay gapless: `prepare_gapless()` reads the neighbouring tracks' edges before anything is replaced, and each track is resampled with that context on the album's sample grid, so the joins equal a one-piece conversion. The Fix dialog and the CLI report gapless joins and exact restores.
- 1.7.0 (2026-11-20): Merged the accuracy work of the parallel "1.2.0" branch into the 1.6.0 line. The source rate is chosen by the −6 dB point against the music's trend (`mid_ratio`, replacing `edge_ratio`), so FFmpeg's default resampler no longer turns a 44.1 kHz master into "48 kHz", which also makes Fix convert such files to 44.1 kHz. A deep cliff test (`deep_cliff_db`, `deep_cliff_strong_db`) catches soft-resampler upsamples that used to pass as REAL, including 48→96 kHz with FFmpeg defaults. The bandwidth ignores content above a gap of more than 3 kHz and is capped at the source Nyquist for upsampled files. The value-grid test (`grid_strength`) catches 16-bit masters converted to 24-bit or float with only a volume change or dither, and many 2× upsamples of 16-bit masters. The converter-noise-floor test (`analog_floor_db`) proves that a dull or old analogue recording was digitised at its high rate (REAL instead of SUSPICIOUS), with a smear zone of 4.3 kHz above `ultrasonic_khz`. Fix rounds 24→16-bit conversions through float, so padded and dithered files come back bit-exactly, and dithers gain-changed grid files. Ctrl/Cmd+A selects every listed file. New `FileResult` fields: `upsample_mid_hz`, `deep_cliffs_db`, `converter_floor_db`, `grid_step`, `grid_bits` and `grid_gain_db`.
